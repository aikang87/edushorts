# 4회차. 웹서버 띄우기: 포트와 환경변수 (목표 1분)

- 슬라이드 = 영상 한 컷(10컷). 슬라이드 자막은 영문 그대로, 슬라이드 노트에도 같은 대본
- `script.txt` = 나레이션용 대본 (영문은 한글 발음, 줄바꿈으로만 구분). `node build.js` 가 자동 생성
- 예상 길이: 낭독 약 65초 (기준: 36자 = 6.7초), 문장 사이 쉼 포함 약 68~70초
- 화면의 명령어/출력은 `commands.sh` 를 실제 실행한 결과(`output/*.txt`), 브라우저 화면은 실제 Chromium 캡처(`output/browser.png`)
- 화면 표시용 편집: 긴 명령은 `\` 로 줄바꿈해 표시(실제 실행은 한 줄), `docker ps` 는 일부 열 생략, 컨테이너 ID는 앞부분만
- 이 환경의 `docker ps` PORTS 는 `0.0.0.0:8080->80/tcp` 만 표시됨. IPv6 가 켜진 PC에서는 `[::]:8080->80/tcp` 가 함께 나올 수 있음

| # | 화면영역 | 자막 |
|---|---|---|
| 1 | 시리즈 타이틀 + 회차 주제 | 이번 시간에는 컨테이너 안의 웹서버를 열고, 설정값을 전달하는 방법을 알아봅니다. |
| 2 | 포트 연결 도식 (내 컴퓨터 8080 → 컨테이너 80) | 컨테이너 안의 웹서버에 접속하려면 내 컴퓨터의 포트와 컨테이너의 포트를 연결해야 합니다. |
| 3 | `docker run -d --name web -p 8080:80 nginx:alpine` (`-p 8080:80` 강조) | docker run에 -p 옵션으로 포트를 연결합니다. 앞의 숫자가 내 컴퓨터, 뒤의 숫자가 컨테이너 포트입니다. |
| 4 | `docker ps` (PORTS 열 강조) | docker ps의 PORTS 열에서 연결된 포트를 확인할 수 있습니다. |
| 5 | 브라우저 `localhost:8080` (nginx 환영 페이지, 실제 캡처) | 브라우저에서 localhost:8080에 접속하면 nginx 환영 페이지가 보입니다. |
| 6 | `docker run ... --name web2 -p 8081:80` + `docker ps` | 포트 번호만 바꾸면 같은 웹서버를 여러 개 띄울 수 있습니다. |
| 7 | 환경변수 도식 (`MY_NAME=Docker` → 컨테이너) | 웹서버에 설정값을 전달하고 싶을 때는 환경변수를 사용합니다. |
| 8 | `docker run --rm -e MY_NAME=Docker nginx:alpine printenv MY_NAME` → `Docker` | docker run의 -e 옵션으로 환경변수를 전달하면 컨테이너 안에서 읽을 수 있습니다. --rm 옵션은 실행이 끝나면 컨테이너를 자동으로 지웁니다. |
| 9 | 옵션 4개 요약 | -p로 포트를 연결하고, -e로 환경변수를 전달하고, --rm으로 자동 삭제합니다. |
| 10 | 다음 회차 예고 (5회차 데이터 지키기: 볼륨) | 다음 시간에는 컨테이너가 지워져도 데이터를 지키는 볼륨을 알아봅니다. |

## 재현
```bash
./commands.sh          # 실제 실행 + output/ 갱신 (Docker 데몬, nginx:alpine, 8080/8081 포트 필요)
node build.js          # ep04.pptx, script.txt 생성 (tools/ 에서 npm install 선행)
../tools/export-png.sh ep04.pptx   # slides/*.png (1080x1920)
```
